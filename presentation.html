The problem · 02 / 07

Great agents are hard to watch.

Terminal-first is powerful

But long model calls and shell actions hide the session’s current state from collaborators and operators.

Logs are retrospective

The durable JSONL trace is useful after the fact. It is not a live surface for progress, steering, or context health.

Resume needs continuity

Reopening a session should restore conversation and sequence state, then accept a fresh human turn cleanly.

Design constraint: keep the existing run loop and session files authoritative. The browser is a local projection, not a second execution engine.

Request lifecycle · 04 / 07

SSE subscribes first, then replays trace.jsonl. A history_complete marker closes the handoff.

02 · START

03 · STREAM

Project activity

The logger persists and broadcasts the same event: model progress, shell work, context changes, stats.

04 · END

Runner status becomes finished or failed; session_ended tells the UI why it stopped.

Resume semantics · 06 / 07

Resume is a new turn, not a fork.

--resume SESSION_DIR

Loads the saved model and conversation history from the trace. Existing events replay into the browser before live events continue.

  • Trace append mode
  • Sequence continues after the last event
  • Prompt becomes the fresh human turn
// restored history [{ role: "user", ... }, { role: "assistant", ... }] // fresh browser message { role: "user", content: [{ type: "input_text", text: "Continue from here…" }] } // append, don’t overwrite seq: last_seq + 1
Guardrails: resume cannot combine with a new prompt destination or scripted steps; terminal resume still requires a TTY.
