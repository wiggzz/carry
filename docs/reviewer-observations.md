# Reviewer observations and bounded wire diagnostics

Primary top-level `instructions` are quoted as immutable, numbered reviewer observations, once per changed value. Initial absent/null/empty direction uses version zero without an empty observation. The latest ledger names the current version: absent/null or empty instructions explicitly clear earlier direction. Earlier versions remain historical evidence, not cumulative instructions. Current task direction and eligible membership/opinions remain in each live ledger. This does not change review cadence or removal eligibility.

Accepted memories retain original `g` source IDs; `m` IDs are only current memory handles. Revision retires the old handle and creates a corrected fact with a new handle; there is no in-place memory-text mutation. Their text appears in a new-memory observation (or once as a materialized shared fact), not in every `current_memories` ledger. Retirement clears reviewer replay history, including old ledgers/answers, so an obsolete fact cannot survive there. Source retirement, native compaction, rebase, and reviewer cleanup retain their coupled projection rules. Native encrypted reasoning and tool pairs still replay unchanged.

Legacy checkpoints without an observation frontier get one explicit, accounted reviewer rewrite (`control_observation_migration`) before their next review. Accepted opinions/facts and primary input survive it. Restart otherwise preserves the committed frontier; invalid reviews cannot advance it. A changed instruction appends a new version without mutating an old prefix. It does **not** independently schedule re-review of previously covered sources; any future admission scheduler must decide that policy explicitly.

## Local diagnostic journal

`review_wire` is recorded immediately before each reviewer HTTP transport attempt, from reqwest's final serialized body, including Codex transformation and authorization retries. Its `request_id` / `review_attempt_id` join the existing numeric `usage` event; an unavailable native input/cache receipt remains unknown, not zero. No primary transport instrumentation is added.

Records contain only fixed item type/role enums, byte/count facts, and domain-separated HMAC-SHA256 fingerprints for ordered items, input prefix, settings, model, cache key, and route. No payload, instructions, arguments, ciphertext, headers, tokens, endpoint text, or source IDs are added. The random key is process-private and never persisted: identities are stable during a process, not across restart. `prior_prefix_equal` is null after restart/eviction/first request or incomplete prior coverage; it compares the exact raw JSON bytes through the previous request's final item boundary, not semantic equality or provider cache behavior.

Hard bounds per attempt: scan at most a 2 MiB wire body; describe at most 48 ordered items; fingerprint at most 256 KiB per item and 1 MiB total item bytes. Oversize bodies/items are explicitly incomplete; omitted/unfingerprinted counts and coverage reason prevent a truncated list claiming a complete match. No full second payload copy or unbounded per-session map is retained. Settings hashing and scanning have fixed byte caps.

The existing private local journal limits remain 16 KiB/record, 64 KiB/session, 256 KiB total, with existing rotation, dropped counters, symlink checks, and fail-open behavior. Comparison reads at most one retained 64 KiB lane. This code changes the bounded default journal, not live service configuration; raw tracing remains separately opt-in.

These changes address repeated request content and make order/prefix changes inspectable. They do not establish a provider cache invalidation bug, fix zero-hit receipts, or prove billed savings or a cost ratio improvement. Full historical membership/feedback ledgers and native reviewer answers still accumulate until existing reviewer cleanup; this is not a full ledger-delta protocol.
