# Reviewer observations and bounded wire diagnostics

Primary top-level `instructions` are quoted once as non-authoritative observed data before conversation sources, after the reviewer's own authoritative instructions and the protocol's stable JSON preamble. Stable instructions stay in that immutable prefix across ordinary reviews and restart, rather than being appended with each ledger. Absent, null and empty initial instructions need no quotation. Current task direction and eligible membership/opinions remain in each live tail ledger. There is no model-facing instruction version or selector. This does not change review cadence or removal eligibility.

Each review has one disposable table of JSON-integer references shared by source groups and existing memories. Source slots preserve the original group annotation numbers where possible, so the index space can be sparse; fact slots follow the original member range. These numbers are references only, not original-member provenance or durable fact identity. No prefix parser, global allocator or legacy wire mode exists. The exact table and HTTP body are captured together before awaiting the reviewer, including background and bounded exceptional reviews. Returned indices are never resolved against a later live history.

The final ledger distinguishes eligible source indices from existing fact indices using its existing purposeful fields. Facts carry their review-local `memory_id` and supporting source indices in both the fact and `current_memories`. Omitted support is recorded in `retained_source_groups`, but is never eligible authority for new facts. A merged projected group resolves to its complete original member union; an omitted canonical separator is not silently included. Admission expands eligible sources once to a sorted original member closure used for deduplication, anchors and storage. Existing fact indices can be protected or retired, never cited as fresh source authority. Invalid items fail closed while valid siblings continue; protection wins conflicts.

Stored advice and facts remain attached to the complete reviewed original prefix. Original source is immutable; economic omission is a reversible request-time projection. Materialized primary facts contain factual text, not implementation-only retirement handles. Reviewer facts retain explicit identity bindings so same-source siblings can be retired separately. Native encrypted reasoning and complete tool cohorts replay unchanged. A caller instruction/settings change is a matching-scope boundary; obsolete advice cannot cross it, including change-then-restore races, while paid receipts still settle to their captured owner. No legacy state or wire-format adapter is provided.

## Memory admission

All active facts contribute their complete serialized/tokenized rendering. Existing hard limits and half-capacity cleanup reserve remain authoritative. Admission uses a disposable projection and does not edit canonical source. The ordinary scheduler and role-neutral actual upstream cache evidence are unchanged. Scripted protocol tests establish rendering, validation and application, not paid-model adherence.

## Local diagnostic journal

`review_wire` is recorded immediately before each reviewer HTTP transport attempt, from reqwest's final serialized body, including Codex transformation and authorization retries. Its `request_id` / `review_attempt_id` join the existing numeric `usage` event; an unavailable native input/cache receipt remains unknown, not zero. No primary transport instrumentation is added.

Records contain only fixed item type/role enums, byte/count facts, and domain-separated HMAC-SHA256 fingerprints for ordered items, input prefix, settings, model, cache key, and route. No payload, instructions, arguments, ciphertext, headers, tokens, endpoint text, or source IDs are added. The random key is process-private and never persisted: identities are stable during a process, not across restart. `prior_prefix_equal` is null after restart/eviction/first request or incomplete prior coverage; it compares the exact raw JSON bytes through the previous request's final item boundary, not semantic equality or provider cache behavior.

Hard bounds per attempt: scan at most a 2 MiB wire body; describe at most 48 ordered items; fingerprint at most 256 KiB per item and 1 MiB total item bytes. Oversize bodies/items are explicitly incomplete; omitted/unfingerprinted counts and coverage reason prevent a truncated list claiming a complete match. No full second payload copy or unbounded per-session map is retained. Settings hashing and scanning have fixed byte caps.

The existing private local journal limits remain 16 KiB/record, 64 KiB/session, 256 KiB total, with existing rotation, dropped counters, symlink checks, and fail-open behavior. Comparison reads at most one retained 64 KiB lane. This code changes the bounded default journal, not live service configuration; raw tracing remains separately opt-in.

These changes address repeated request content and make order/prefix changes inspectable. They do not establish a provider cache invalidation bug, fix zero-hit receipts, or prove billed savings or a cost ratio improvement. Full historical membership/feedback ledgers and native reviewer answers still accumulate until existing reviewer cleanup; this is not a full ledger-delta protocol. Native answers may themselves contain accepted memory text and remain unmodified; the observation frontier prevents additional copies per ledger, not copies already present in native evidence.
