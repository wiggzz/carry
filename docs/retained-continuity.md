# Continuity across selective omission

The reviewer should preserve useful conclusions and completed-work outcomes as
brief factual memories before releasing their only useful source. Unfinished work
needs equally concise continuity: actual status, next action, relevant branch or
artifact/evidence pointers, and unresolved blockers. These are work records, not
restatements of human instructions. No new fact is needed when sufficient context
already remains elsewhere or the information is no longer useful. The reviewer
can still aggressively release redundant detail; memories can later be revised
or retired under the existing protocol.

Existing source eligibility, byte/token admission and memory limits remain
authoritative. If a proposed memory fails validation or admission, its identifiable
eligible supporting groups stay protected, including at background merge when
concurrent history growth exhausts the budget. Feedback gives the rejection
reason and notes source preservation. Other valid drops remain valid; a memory
is not mandatory for every removal. This fallback cannot discover an unwritten
memory or validate its meaning, and it does not invent a work outcome.

After a selected source rewrite, primary history contains one neutral user-role
notice per contiguous run of removed native items:

> [Earlier conversation omitted by Carry; retained messages remain in original order.]

The notice reveals only absence: no source IDs, removed content, removal opinions,
completion claim, recovery promise or instruction. It has no native source ID.
Unchanged histories and advice without a selected removal have no notice.
Replacement memories remain after their latest complete source group; they do
not split omission runs. Notices are derived from persisted removal flags on each
render, so repeat rendering, coalescing later removals and restart do not accumulate
extra notices. Canonical history and native tool/reasoning cohorts are unchanged.
Reviewer source replay is still pruned by the same selection, with accepted facts
and current eligibility kept separately; primary notices are not eligible sources.

This is the default primary rendering, with no new client option or checkpoint
field. Already-compacted checkpoints acquire notices on their next render, so
old cache receipts match only an unchanged exact prefix. The actual primary
render (including notices and facts) remains the input to token/capacity planning
and cache-slot identity mapping. Added text can change rewrite payoff and cache
reuse; no savings improvement is claimed.

Credential-free scripted tests exercise selected rendering, complete tool groups,
accepted outcome/WIP facts, actual proxy restart, rejected replacements and
background merge. They verify the pipeline, not whether a live reviewer will
follow the new guidance or write sufficient memories. No live-model adherence or
semantic-safety evaluation is included.
